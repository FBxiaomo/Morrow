# 能力规格 · 氛围渲染（atmosphere-rendering）

> 适用版本：0.2.1（反向成文） · 主要代码：`src/atmosphere/`（landscape / photographic / real-weather / glyph-surface / window-glass / volumetric）
> 本域是性能预算与降级链的权威规格。

## 概述

单一 Canvas2D 主绘制循环（`Landscape`）承载背景与天气氛围，按需叠加写实粒子、数字互动、体积云与窗玻璃 WebGL 通道。渲染随天气与昼夜连续插值，页面隐藏即停画，预算超限自动降档。

## 需求

### 主循环与预算

- **FR-AT-01** 系统应以 `requestAnimationFrame` 驱动唯一主绘制循环；帧预算：默认 33ms、写实档 16ms、轻量档 66ms。
- **FR-AT-02** 系统应把 DPR 限制在 ≤ 1.5（轻量档 1.0）。
- **FR-AT-03** 当 `document.hidden` 时，系统应停止全部背景绘制；重新可见后恢复。
- **FR-AT-04** 当系统设置 `prefers-reduced-motion` 或用户选择静态画面（`appearance.motion: off`）时，系统应冻结画布（连续两帧截图 SHA-256 一致，有测试断言）。
- **FR-AT-05** 天气状态切换应在约 1.4s 内完成连续插值过渡（七分类各自的云/雨/雪/雾/暗五通道强度表驱动），不发生跳变。

### 昼夜与背景

- **FR-AT-06** 系统应在有日出日落数据时按真实 ±35 分钟判定黄昏，否则回退本地时段（5–7 点黎明、17–19 点黄昏）计算昼夜相位（day/dusk/night）。
- **FR-AT-07** 系统应按 `background.type` 合成背景：摄影风景板（按昼夜/天气调色，缓存键量化）/ 渐变 / 纯色 / 自选图片（IndexedDB 读取带 revision 守卫）。
- **FR-AT-08** 如果摄影板不可用，系统应回退到程序化背景（渐变天空 + 星点 + 日月 + 分层山脊 + 雾霭），保证画面永不空白。

### 主题差异化渲染

- **FR-AT-09** 当主题为 studio（数字工作室）时，天气粒子应**与其他主题同源**：写实档同样创建写实天气粒子与数字打湿互动（预算、帧率档与粒子上限同 FR-AT-01/10），轻量档回落到主循环简笔雨丝；室内光投影保留受光墙的亮度蒙版投影、随天气变冷变暗、雪天雪斑、云影与雷光脉冲，作为氛围叠加而非雨的载体（雨天墙面不单独绘制雨纹）。全屏雾团与天际电弧仍仅限室外主题（studio 的雾由室内雾光、雷由室内雷光脉冲回应）。
- **FR-AT-10** 当写实档开启时，系统应创建写实天气粒子（雨 ≤ 700 / 雪 ≤ 180 / 附着水珠 ≤ 100 / 溅射 ≤ 240 / 玻璃珠 ≤ 48），各主题一致；window 主题的干燥数字例外见 FR-AT-20。

### 数字互动（打湿）

- **FR-AT-11** 当 `weather.wetClock` 开启、写实档、非 window 主题时，系统应让雨滴与时钟数字发生像素级碰撞：击字成珠、水珠沿笔画下滑坠落、溅射；湿润区保留高光；雪在数字顶部堆积。
- **FR-AT-12** 字形碰撞面应在几何变化（字体/字号/视口/秒数字变化）时重建，且仅几何变化时重建（`clock-layoutchange` 驱动）；碰撞检测应做扫掠防隧穿。
- **FR-AT-13** 当用户关闭雨雪互动开关时，系统应停止全部互动绘制并释放资源；重新开启可恢复。
- **FR-AT-14** 湿润数字应跨秒更新持续存活（秒变化不擦除已有水珠，有测试断言）。

### 体积云

- **FR-AT-15** 当写实档、云量 > 0.25、非 studio、scene 背景时，系统应启用体积云 raymarch 渲染；画布 ≤ 180k px（lite ≤ 90k），结果缓存 + 10/18fps 节流。
- **FR-AT-16** 如果体积云 WebGL 不可用，系统应回退 Canvas 云层，不报错不空白。

### 窗边玻璃（WebGL）

- **FR-AT-17** 当写实档、`weather.glass` 开启、主题为 window、且雨强度超过阈值时，系统应启用 WebGL 玻璃雨（下滑水柱 + 驻留凝结珠 + 位移折射 + 水痕），帧缓冲 ≤ 1.8M px、背景纹理上传 ≤ 30 次/秒。
- **FR-AT-18** 如果 WebGL 创建/编译失败或发生 `webglcontextlost`（含测试主动触发 loseContext），系统应回退到 Canvas 玻璃水珠（含背景折射采样），再不可用则回退简单前景水滴；回退当前渲染器经 `data-window-glass` 通道暴露。
- **FR-AT-19** 在禁用 WebGL 的浏览器中，窗边主题仍应呈现可用的玻璃回退（有测试断言）。
- **FR-AT-20** 窗边主题的画面层级应为：背景 → 玻璃 → DOM 窗框 → 时钟数字（z 顺序有测试断言：frame > glass，clock > frame）；窗边主题的数字保持干燥（打湿互动不生效），切回其他主题后互动恢复。
- **FR-AT-21** 当玻璃开关/画质/主题/自选天气变化使条件不再满足时，系统应即时释放 WebGL 资源（`dispose` + `WEBGL_lose_context`），不残留绘制。

### 可观测性

- **FR-AT-22** 系统应通过 `diagnostics` getter 暴露：帧数、平均/峰值绘制毫秒、效果与玻璃启用状态、云渲染器、雪色、以及写实粒子的碰撞/滴落/溅射统计，供回归测试断言。

## 设计约束与不变量

- 麦克风律动（`audio.enabled`，实验功能）经 `landscape.audioLevel` 注入主循环；音频只在本机处理，不上传。
- 秒进度、闪电（递归中点位移电弧 + 双闪包络）、雾霭等效果一律走主循环统一调度。
- 渲染层只读设置与服务状态，不反向写 UI。
- 帧率预算超限的处理策略是「按档降载」（预算见 FR-AT-01/02/15/17），不存在用户可感知的报错路径。
