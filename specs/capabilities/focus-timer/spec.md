# 能力规格 · 专注计时（focus-timer）

> 适用版本：0.2.1（反向成文） · 主要代码：`src/data/pomodoro.ts`、`src/ui/focus.ts`

## 概述

完整专注闭环：任务意图 → 时长选择 → 计时（可暂停/继续/结束）→ 阶段推进（work/short/long）→ 到时反馈（页面 + 可选系统通知）→ 本地历史与今日统计。计时为**时间戳驱动**：精度不依赖页面存活，后台/休眠/跨刷新均不丢失。

## 需求

### 进入与设置

- **FR-FOCUS-01** 当用户按下空格（非活跃态）或点击工具条「专注」时，系统应打开专注面板，呈现任务意图输入（≤ 80 字、带示例占位）、15/25/45 分钟快捷时长（写回 `focus.work`）、今日已完成统计与系统通知开关。
- **FR-FOCUS-02** 当用户点击「开始」时，系统应以当前任务与时长进入 running 态并持久化快照（`desktop.v2.pomodoro`）。

### 计时与状态机

- **FR-FOCUS-03** 系统应以 `elapsedMs = (pausedAt ?? now) - startedAt` 计算进度，**永不累积计数器**；暂停恢复时平移 `startedAt`，后台与休眠不损失精度。
- **FR-FOCUS-04** 当工作段计时结束时，系统应推进阶段：第 4 段后进入长休（`focus.long`），其余进入短休（`focus.short`）；休息结束回到工作段；阶段推进触发 `'phase'` 事件。
- **FR-FOCUS-05** 系统应支持一次最多补算 500 个阶段边界（`MAX_CATCHUP`），超出部分不再逐段推进。
- **FR-FOCUS-06** **长时间离开规则**：如果离开时长超过「当前阶段 + 下一阶段」总长，系统应触发 `'return'` 事件——重置起点并置于暂停态，等待用户确认后继续，**不虚构一串“已完成”的阶段**（页面显示离开说明）。
- **FR-FOCUS-07** 当用户在活跃态按空格时，系统应在暂停与继续之间切换；**连续快速两次空格不得结束专注**（有专项测试断言）。
- **FR-FOCUS-08** 当用户点击「结束」时，系统应终止当前专注：工作段且未暂停时计入历史，休息段不记录。
- **FR-FOCUS-09** 系统应在跨刷新后恢复进行中的专注（快照从 localStorage 读取；损坏数据安全回退 idle 态，不抛错）。

### 到时反馈与记录

- **FR-FOCUS-10** 当工作段完成时，系统应在页面呈现完成回顾（任务名 + 分钟数 + 「再开始一段」入口）。
- **FR-FOCUS-11** 当阶段推进时，系统应显示 toast；若 `focus.notifications` 开启且已授权，应同时发送系统通知（`tag: 'horloge-focus'`）；设置内应说明「计时保存在本机。浏览器关闭后无法发送系统通知」。
- **FR-FOCUS-12** 当用户开启通知开关时，系统应立即请求 `Notification` 权限，拒绝则仅保留页面 toast。
- **FR-FOCUS-13** 系统应把完成的专注写入本地历史（上限 100 条：时间、分钟数、任务名，无任务名记「无标题专注」）；分钟数 < 1 不记录。
- **FR-FOCUS-14** 系统应按本地日期聚合「今日 N 段 · M 分钟」用于主桌面提示与专注面板统计。
- **FR-FOCUS-15** 设置页应提供三个时长调节（工作 5–60 步 5 默认 25 / 短休 1–15 默认 5 / 长休 5–30 步 5 默认 15）与「结束本次专注」入口；修改即时生效并持久化。

### 误触防护

- **FR-FOCUS-16** 当 Esc 刚关闭任意面板（含专注面板）后 400ms 内到达的空格，系统应丢弃，不触发「打开专注」。

## 设计约束与不变量

- 状态机由主装配的 200ms tick 驱动 `normalize()`；事件集：`start / pause / resume / stop / phase / return`。
- 快照与历史键：`desktop.v2.pomodoro` / `horloge.focus-history.v1`（迁移受 Morrow 提案约束）。
- running 态的主桌面呈现：工具条专注按钮高亮并显示剩余时间；桌面显示专注状态行 + 专注进度（与秒进度条相互独立）。
- 面板背景点击可关闭面板（不结束计时）。
