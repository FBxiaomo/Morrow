# 变更提案 · 2026-11-23-settings-right-dock

> 状态：**已归档**（增量已合并进 `specs/capabilities/themes-personalization/spec.md`，FR-TH-18/19）
> 提出日期：2026-11-23 · 提出人：用户（会话）
> 影响能力域：`specs/capabilities/themes-personalization/`（设置面板结构）、`specs/capabilities/interaction-shell/`（Esc 链路复核，行为不变）

## 1. 为什么改

设置面板当前是 `showModal()` 居中模态弹窗（宽 min(880px, …)），带全屏暗化背景与 7px 背景模糊。用户调整外观/主题时**看不到主画面的实时效果**，只能来回开关面板比对。用户诉求：以右侧边栏打开，不遮挡主页面，实时看到更改效果。

## 2. 改什么

设置面板改为**非模态右侧停靠边栏**：`dialog.show()`（非模态、无 backdrop、不阻断主页面交互），面板固定停靠视口右侧、全高、宽约 420px；主画面保持可见且可交互（工具条、快捷键照常工作）。关闭途径不变：右上角关闭按钮、「完成」按钮、`Esc`（Shell.onKey 链路，FR-SH-04 优先级不变）。窄屏（< 700px）呈全屏工作表。打开时焦点移入面板，关闭时还原先前焦点（既有行为保留）。

**影响的既有需求**：
- FR-TH-16：不动（五页与几何稳定断言继续成立）；
- FR-TH-17：不动（不透明底色要求继续成立）；
- FR-SH-01/04：不动（快捷键与 Esc 优先级行为不变，非模态下 Esc 仅由 Shell 处理，链路已存在）。

## 3. 不改什么（边界）

- 不改设置项 schema、控件生成体系、存储与导入导出。
- 不改面板内信息架构（五页划分、页脚、tab 导航结构）。
- 不做「打开面板时主画面避让偏移」（时钟若被用户摆到最右侧，会被边栏覆盖——当前取舍，见决策待办）。
- 不加「拖拽调整边栏宽度」「记忆开合状态」等新能力。
- 不改专注弹窗（focus dialog）的模态形态。

## 4. 需求（EARS，确认后才可设计）

- **FR-DOCK-01** 当用户打开设置面板且视口宽度 ≥ 700px 时，系统应以非模态右侧停靠边栏呈现：面板右缘贴齐视口右缘、全高（100dvh）、基础宽约 420px（≥1000px 视口沿用既有打磨层 460px），主画面不被暗化背景遮挡且保持可见。
- **FR-DOCK-02** 当设置面板打开时，系统应保持主页面可交互：工具条按钮与全局快捷键（含 `1`–`4` 主题切换）照常生效，点击面板外区域不关闭面板（关闭仍经按钮或 `Esc`）。
- **FR-DOCK-03** 当视口宽度 < 700px 时，系统应以全屏工作表呈现设置面板（inset 0、无边框圆角差异）。
- **FR-DOCK-04** 当面板打开时，系统应把键盘焦点移入面板；当面板经按钮（关闭/完成）关闭时，系统应还原打开前的焦点；当面板经 `Esc` 关闭时，系统应把焦点交还页面（既有防误触空格行为，FR-SH 链路不动）。
- **FR-DOCK-05** 系统应保持 FR-SH-04 的 Esc 优先级不变：`Esc` 先关设置面板，再关专注面板，再退纯净显示。
- **NFR-DOCK-01** 系统应保持 FR-TH-16/17 既有断言继续成立：五页切换几何稳定、底色不透明度 ≥ 0.9、打开面板不改变时钟与主画面几何。
- **NFR-DOCK-02** 系统应使面板入场动画自右侧滑入，`prefers-reduced-motion` 时禁用（既有全局短路）。

## 6. 决策待办（需要人拍板的问题）

- [x] 窄屏（< 700px）形态：全屏工作表（提案倾向）vs 维持现状居中模态。**已确认：全屏工作表。** 手机上 420px 边栏本就近全屏，全屏工作表是标准形态，且统一非模态代码路径。
