# 变更提案 · 2026-11-24-city-picker-main-zone

> 状态：**已验证 · 已归档**
> 提出日期：2026-11-24 · 提出人：用户（会话需求）
> 影响能力域：`specs/capabilities/time-display/`（主），`specs/capabilities/settings-storage/`（次：新设置键登记）

## 1. 为什么改

- **添加城市的方式反人类**：世界时钟目前要求用户在设置里手打逗号分隔的城市串（`content.cities` 文本框，FR-TD-13 的事后校验文案本身就证明了交互失败——「城市未收录」「时区名称不存在」这些错误本不该由用户拼写触发）。用户表述：「改为列表搜索添加进已加入城市」。
- **主时钟锁死本机时区**：主桌面时钟只能显示本机时间。用户表述：「可以把主时钟改为去其他时区」——希望把整个钟面当作其他城市的时钟使用。

## 2. 改什么

两件事，共用同一套内置城市/时区数据：

1. **世界时钟改为搜索点选添加**：设置面板「世界时钟」组改为「搜索框 + 结果列表 + 已加入城市 chips」。搜索内置城市表（中文名与英文别名双向匹配），点击结果即添加进已加入城市；chips 可单个移除；无匹配时可按 IANA 时区名直接添加（高级兜底）。**数据键 `content.cities` 与逗号分隔格式不变**——旧数据、导入导出、主题 profile 全部无迁移兼容。
2. **主时钟可选时区**：新增设置键 `content.clockZone`（select，默认 `auto` 跟随本机）。切换后主时钟的时:分、AM/PM、日期、农历/节气**整体**按所选时区呈现（已确认决策）；秒进度与秒数仍为全局秒，月相仍为天文近似（与时区无关）。选项为「跟随本机」+ 内置城市去重后的时区（代表城市名标注）。

**影响的既有需求**（`capabilities/time-display/spec.md`）：

| 编号 | 处置 |
| --- | --- |
| FR-TD-06（本地日期）、FR-TD-07（农历节气） | **修订**：按 `content.clockZone` 所选时区呈现，`auto` 时行为不变 |
| FR-TD-09（世界时钟显示）、FR-TD-10（5 城上限）、FR-TD-11（三级解析）、FR-TD-12（无效条目解释） | 不动（显示行为不变；无效条目仍可能来自导入配置/旧数据，保留解释） |
| FR-TD-13（文本框即时校验） | **修订**：校验反馈随新交互迁移到搜索结果与 chips（无效 chip 标错并给原因） |
| FR-TD-14/15/16、NFR-TD-01 | 不动 |

## 3. 不改什么（边界）

- `content.cities` 键名、逗号分隔格式、5 城上限、三级解析顺序——全部保留，**无存储迁移**。
- 主界面世界时钟行的渲染样式与位置（`.world-clocks`）不动。
- 快捷键层不新增按键（主时钟时区只在设置面板切换，已确认）。
- 天气模块的昼夜/时区行为不动（天气仍由天气源驱动）。
- 月相计算不动（全局天文现象，与时区无关）。
- 专注计时、通知、PWA 均不动。
- 城市搜索为**本地内置表**过滤，不引入地理编码网络请求（R12 边界同理）。

## 4. 需求（EARS，确认后才可设计）

- **FR-TD-17** 当用户在「世界时钟」搜索框输入关键字时，系统应从内置城市表按中文名与英文别名双向匹配过滤，并展示匹配结果列表（含城市名与该时区当前时间），无需联网。
- **FR-TD-18** 当用户点击搜索结果中的城市时，系统应把它追加进已加入城市并立即在主界面世界时钟生效；如果该城市已在列表中，则应提示重复而不追加。
- **FR-TD-19** 当已加入城市达到 5 个时，系统应禁用搜索添加并说明上限；移除后恢复可添加。
- **FR-TD-20** 当内置表无匹配时，系统应允许按 IANA 时区名（如 `Asia/Shanghai`）直接添加；如果无法解析，则应给出原因提示且不改列表。
- **FR-TD-21** 已加入城市应以 chips 呈现且每个可单独移除；如果某 chip 是无效条目（来自旧数据或导入配置），系统应在该 chip 上标示错误样式并悬浮给出原因（与 FR-TD-12 同源原因文案）。
- **FR-TD-22** 当用户把 `content.clockZone` 设为某内置时区时，系统应将主时钟的时:分、AM/PM、日期、农历与节气整体按该时区呈现，立即生效并持久保存；当设回 `auto` 时应恢复本机时间。
- **FR-TD-23** 如果 `content.clockZone` 的持久化值非法（如导入配置携带坏值），系统应回退到 `auto` 并按本机时间呈现。
- **NFR-TD-02** 系统应始终使搜索结果项与 chip 移除按钮满足触控目标 ≥ 40px、文字 ≥ 11px（与 R9 一致）。
