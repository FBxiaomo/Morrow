# 变更提案 · 2026-11-24-font-cards

> 状态：**已归档**（增量已合并进 `specs/capabilities/themes-personalization/spec.md`，FR-TH-12/13 修订）
> 提出日期：2026-11-24 · 提出人：用户（会话）
> 影响能力域：`specs/capabilities/themes-personalization/`（字体与外观 FR-TH-12/13 修订）、`specs/capabilities/offline-pwa/`（sw 核心缓存清单）

## 1. 为什么改

当前字体选择有两处体感问题：

1. **选择不直观**：内置 8 种风格是纯文字下拉（「轻盈 · Light」「衬线」），看不到实际字形；本机字体模块挤了 6 个控件（读取按钮、搜索框、分页列表、手动输入、应用、清除），走完「读取 → 授权 → 搜索 → 翻页 → 点选」五步才能用上。
2. **字体贫乏**：8 个风格里只有得意黑真正打包进项目，其余全是系统字体栈拼盘（Avenir Next / Didot 仅 macOS 有），Windows 上几乎全部回退成微软雅黑，实际可感知差异很小。

## 2. 改什么

字体模块改为**预览卡片网格**：每张卡片用该字体栈真实渲染 "12:48" 大号预览，点选即用、当前项高亮；「读取系统字体」降级为网格下方单一入口，读取后本机字体汇入同一网格的本机分区（保留搜索），删掉手动输入/应用/清除等冗余控件（选择任一内置卡片即退出本机字体覆盖，既有行为）。同时新增 1 个打包内置字体：**Playfair Display**（SIL OFL 开源）数字/latin 子集 woff2，接替依赖 macOS 的 Didot 栈作为优雅衬线代表。

**影响的既有需求**：
- FR-TH-12：修订（内置风格数量 8 → 9，选择控件从下拉改为卡片网格）；
- FR-TH-13：不动（本机字体读取、权限拒绝指引、真实平台字体验证全部保留）；
- offline-pwa 的 sw CORE 清单：修订（新增字体资源，缓存版本升级）。

## 3. 不改什么（边界）

- `appearance.fontCustom` 存储键与其迁移语义不动；queryLocalFonts 权限流程与失败文案不动。
- 主题默认字体与四主题 profile 默认值不动（Playfair 只是新增可选项，不改变任何默认）。
- 不引入在线字体服务、不打包中文 webfont（霞鹜文楷已拍板不做）。
- 字号/字重/字距的既有全局规则不动（自定义字体重置字重 400 的行为保留）。

## 4. 需求（EARS）

- **FR-FONT-01** 当用户打开外观页时，系统应以预览卡片网格呈现全部内置字体风格（9 项，含新增 Playfair），每张卡片以对应字体栈渲染 "12:48" 预览，当前生效项以 `aria-pressed` 高亮（有测试断言）。
- **FR-FONT-02** 当用户点击任一内置卡片时，系统应立即应用该字体风格并清空本机字体覆盖（既有行为保留，有测试断言）。
- **FR-FONT-03** 系统应把 Playfair Display 以项目内置 woff2（latin/数字子集，21.8KB）提供：经 Vite 打包随 CSS 引用，`font-display: swap` 加载前回退系统衬线；sw 惰性缓存使其首次加载后离线可用（与得意黑同链路），体积 ≤ 80KB（有测试断言）。
- **FR-FONT-04** 当用户点击「读取系统字体」并授权后，系统应把本机字体以卡片形式汇入同一网格的本机分区，支持中英文搜索、点选即用（既有锚点保留：`选择字体 X` aria-label、`已读取 N 个字体家族`/权限拒绝状态文案、`.font-option` 列表项，有既有用例覆盖）。
- **FR-FONT-05** 系统应删除手动输入框、应用按钮与独立清除按钮；「退出本机字体」由点击任一内置卡片完成（无死控件，有 DOM 断言）。
- **NFR-FONT-01** 系统应保持设置面板「打开不改变主画面几何」与五页几何稳定断言继续成立。
